# Personal Workspace V4 — Capability Matrix

Whole-product capability mapping for V4, already independently reviewed. Each page
is classified against the canonical core so V4 implementation knows what is proven,
what is partial, what is presentation-only, what is a true domain gap, and what is
deferred.

## Classification Legend

- **PROVEN_CANONICAL** — full canonical authority exists; UI-ready.
- **PARTIAL_CANONICAL** — core authority exists; known enrichment gaps (non-blocking).
- **UI_ONLY** — path/identity exists; no full canonical authority yet.
- **TRUE_DOMAIN_GAP** — canonical authority missing; must be solved before the
  owning page can be declared complete.
- **DEFERRED** — future scope; not implemented automatically.

## Actions

**PARTIAL_CANONICAL** — current canonical Actions are usable for V4. Known
enrichment gaps exist:

- Category
- Notes
- Linked Area / Luminaire
- Linked Comment
- Display Action ID
- Open Linked Record

These do **NOT** block V4 foundation. They require a future owner decision before
any schema/domain expansion.

## Comments

**PARTIAL_CANONICAL** — current reviews/comments authority exists. Later enrichment
gaps include:

- threading / replies
- client / internal origin
- luminaire relation

Do not implement automatically.

## Datasheets / Images

**UI_ONLY** — path identity exists. Future registry remains later scope.

## Packages

**PARTIAL_CANONICAL** — canonical package write authority exists. Full Golden
seedability requires real CANONICAL rendered-file conditions.

## Submissions / Issue History / Register

**TRUE_DOMAIN_GAP** (later canonical authority gaps). They do **NOT** block F0/F1/F2.
They must be solved before those owning pages are declared complete.

## Deferred

Any enrichment (Actions Category/Notes/linking, Comments threading/origin,
Datasheets registry, Submissions/Issue History/Register authority) is deferred to
a future owner decision. No new product capability is silently added.
